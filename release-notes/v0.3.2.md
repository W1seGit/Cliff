# Cliff v0.3.2

## Servers and files

- Updates warn before stopping a running server and start it again afterwards. The update pop-up only claims that worlds are untouched.
- The file manager can rename files, move them into folders (including by drag and drop) and has a **Safe mode** that refuses to move or delete important files such as `run.bat` or `server.properties`. You can turn it off.
- `server.properties` now lives in the server's Rules section under Advanced, replacing the Advanced tab.
- Creating or importing a server shows what it is doing step by step, with download progress, and no longer shows a false warning when everything is configured. The Create and Import pages have a clear switch between them.
- The server actions menu has icons, and the double hover on server rows is gone.

## App settings

- A new **Service** tab can stop or restart Cliff. Running servers are stopped first (after you confirm) and start again after a restart.
- Fixed a bug where opening App settings and then another page left you stuck on the server's Overview.

## Install and uninstall

- `cliff uninstall` asks whether to **keep your data** (removes only Cliff, your servers and settings stay) or **delete everything** (you must type `delete`). `--keep-data` and `--delete-data` do the same without asking.
- The installers accept `--data-dir` and `--server-root` (`-DataDir` and `-ServerRoot` on Windows). Existing folders are reused, missing ones are created, and the choice is remembered. `cliff configure` changes it later.
- Installing into a folder that only holds `data/` and `servers/` (what is left after keeping data) reuses it.

## Performance and reliability

- The dashboard is served compressed, and the logos and icon are much smaller, so the download and first load are lighter (the packaged web folder shrank from 2.3 MB to 1.6 MB).
- The daemon has a soft memory limit of 256 MB (`CLIFF_MEMORY_LIMIT_MB`, `0` turns it off). `daemon.log` warns when its memory gets high and when it recovers.
- A crash writes a report to `logs/crash-<time>.log`, and the next start tells you about it. Errors in web requests are now logged with their details.
